# 工资辅助计算工作台 · 开发文档

> 版本：V2.1（截至 2026-10-01 状态）
> 形态：基于 WorkBuddy「资料库」Skill 的**单文件 HTML 应用**
> 运行环境：资料库协作态（在线页面 + 内置数据库 SDK），移动端 PWA 友好

---

## 1. 项目概述

### 1.1 目标
面向**丝印 / 移印车间**的计件工资辅助核算工具，打通「金蝶生产用料清单 → 开工确认 → 组级金额分摊 → 个人工资表 → 财务审核」全链路，替代手工 Excel 分摊，解决：
- 按组计件、按成员系数分摊的核算繁琐；
- 工单开工状态、结算状态不透明；
- 工资表与工单关联、审核流转缺失。

### 1.2 技术栈
| 层 | 选型 |
|---|---|
| 前端 | 原生 HTML + CSS + 原生 JS（单文件，无构建步骤） |
| 存储 | WorkBuddy「资料库」6 张在线数据表（云端，非自建 DB） |
| 数据访问 | 资料库运行时注入的 `window.__SMART_PAGE__.database` SDK |
| 部署 | 资料库 Skill `import_html.py` 原位写入协作态页面 |
| 样式 | CSS 变量主题，响应式（桌面侧栏 / 移动底部 Tab） |

### 1.3 关键事实
- 页面**必须经由资料库分享链接打开**才能使用 SDK（直接双击本地 HTML 文件，`db` 为 `null`，仅渲染空态）。
- 所有写操作（增 / 改 / 删）走 SDK；读操作走 `query` 翻页拉全量后在前端 `ST` 内存态筛选渲染。
- 资料库 SDK 可能在页面脚本之后才注入，故 SDK 句柄在每次交互入口通过 `attachDb()` 重新获取（**绝不顶层缓存一次**）。

### 2.2 部署 / 上传命令（铁律）
通过资料库 Skill 的 `import_html.py` 上传，**必须带 `--databases` 并列出全部 11 张表**，否则页面未关联数据表，SDK 读写被拒且常被 `.catch` 静默吞掉：

```bash
python import_html.py \
  "工资辅助计算工作台.html" \
  --node-block-id M0TIXtwP3MogyZsqUVYiVm \
  --databases '[{"id":"gZY0sbhPvQ5ej8oiyMem6H"},{"id":"KkppEh3EZOoDCG7CGEIClc"},{"id":"neDa3mDiWHRZv3ODUPHF5D"},{"id":"UoCdYGNsk45naOBKd1ti9v"},{"id":"geEidg2IPE7ybQEA92gUNQ"},{"id":"aaxVgZjDi3tZiLZIQEp16i"},{"id":"8dD44gp6f5yagWBa64Muwl"},{"id":"LSFlG7HjOsbf6MBeX4YvXk"},{"id":"A09cAzQY9OYrO7zyJTUgnz"},{"id":"OOYKF8VbGGJz2PS8zoSbwC"},{"id":"7XynwxGbwPCoECntdCzKpz"}]'
```

> ⚠️ **漏 `--databases` 是最常见故障**：表现为「保存 / 删除没反应」但无报错。静态校验还要求每个 `databaseId` 为**字符串字面量**（见 §9）。
> ⚠️ **表被误删的排查（V3.0 实战）**：上传报 `bind page-database relation … permission denied` 时，先用 `get_database_schema.py --database-id <id>` 确认真实错误——若返回 `database not found: cannot resolve space_id` 说明**表已被删除**（不是权限问题），需重建并同步替换页面内全部 11 处引用。本项目 staff 表曾被删，重建为 `KkppEh3EZOoDCG7CGEIClc`。

### 4.2 计件复核（自动计算 · 复核）· `sec-paystat`（V3.2 替代原「开工确认」页；V3.8 由「工资统计」改名）

**不是手工录入**，而是由系统按生产任务单的**开工日期**自动算出，统计员在此页**复核或修改**。

**核算单元 = 「生产任务单 × 用料明细」（V3.3）**：每行对应某张工单的一条用料子项，保留工单号与物料的对应关系。

**计算链路**（`computePayStat()`）：
```
1) 取 orders 中 业务状态∈{开工,完工} 且有「开工时间」且有「加工组别」的工单
2) 按 开工时间 所在月份 → 工资月份（如 2026-10-05 → 2026-10）
3) 用 material 按【任务单号】取该单**全部**用料子项（不能按单个子物料代码过滤，否则漏算）
4) 子项单价 = price 表中（子物料代码 + 工序名称）匹配的单价
5) 【核算单元】明细金额 = 该条子项的 子项数量 × 子项单价
6) 【工单组级金额】= 该工单内所有子项明细金额之和（该工单整个组的总额）
7) 分摊比例 = 个人系数 ÷ 该组在职成员系数和
   个人金额 = 工单组级金额 × 分摊比例
```

**关键区别（V2 → V3.3）**：
| | V3.2（按组+月聚合） | **V3.3（按明细核算）** |
|---|---|---|
| 聚合维度 | 组 + 工资月份 | **每张工单的每条用料明细** |
| 任务单号 | 拼接成「MO001、MO004」 | **每行对应唯一一张工单** |
| 明细区分 | 合并同物料，看不出对应工单 | **保留 任务单 × 物料 的对应关系** |
| 金额列 | 只有一个「组级金额」（全组总额逐行重复） | **明细金额**（该条子项）+ **工单组级金额**（该工单该组总额） |

> 同一工单的同一成员，多条明细的**个人金额相同**（分摊按工单组级总额算，与具体明细无关）；但**明细金额各行不同**。因此「同一工单某成员的明细金额之和 = 该工单组级金额」。

**工资月份规则（V3.1 核心）**：
- 工资月份**以录入日期所在月份为准**。
- 录入时「工资月份」留空 → 自动取录入日期的月份（`monthOf(录入日期)`）。
- 历史数据若 `工资月份` 为空 → `payStatMonth(r)` 渲染时按录入日期回填，**不会漏归集**。

**金额规则**：留空自动 = 工价 × 数量（表单内实时联动计算，`#psCalc` 显示算式）；手工填值则覆盖。

**三种录入方式**：
| 方式 | 入口 | 说明 |
|---|---|---|
| 单条 | 「＋ 新增一条」 | 表单录入，工价/数量变动时金额实时算 |
| 批量粘贴 | 「批量录入」 | 多行文本框，**从 Excel 直接复制整块粘贴**（制表符或逗号分隔，自动跳过表头行） |

**批量录入列顺序**（`PS_BATCH_COLS`）：
```
工资月份 → 录入日期 → 生产任务单号 → 小组 → 员工姓名 → 工号 → 工种 → 品名 → 单位 → 工价 → 数量 → 金额 → 备注
```

## 5. 核心业务流程

### 5.1 生产任务单状态机（V2.5，V2.6 增加用料清单联动）
```
【业务状态】计划 ──开工提交(openStartSubmit)──▶ 开工 ──确认(openTaskDone)──▶ 完工
                   │                              │                        │
                   ├─ 记录开工时间                ├─ 回写完工入库数        └─ 清单状态→完工
                   ├─ 写 confirm 记录             │
                   ├─ 结算状态→已提交            │
                   └─ ⚡调用金蝶接口→生成用料清单 ─┘（清单状态=开工）

【结算状态】待结算 ──开工提交──▶ 已提交 ──生成工资表(自动)──▶ 已提交(保持)
                                        └─财务审核通过──▶ 已结算
```
- 开工提交（`openStartSubmit`）：写 confirm 记录 + orders 设「业务状态=开工 / 开工时间=now / 开工确认状态=已确认 / 结算状态=已提交」。
- 确认完工（`openTaskDone`）：仅 `业务状态=开工` 可操作，置「业务状态=完工」+ 完工确认人 / 完工数量 / 完工时间。
- 生成工资表（`genWageSheet`）：工单「已确认未结算」→ 结算状态保持「已提交」（不在此置已结算）。
- 财务审核（`auditWage` / `doWageAudit`）：wage 置「已审核」+ 同组已确认工单结算状态置「已结算」。
- 两条状态线互不覆盖：业务状态管生产进度，结算状态管工资结算。

### 5.2 开工确认（doConfirm）
1. 选择确认组别 `cGroup` + 确认人工号 `cLeader`；
2. 勾选待确认工单（`[data-ck]`）；
3. 对每条：写 confirm 记录（确认数量=产品数量）+ orders 更新 `开工确认状态=已确认`、`加工组别=所选组`；
4. 全部 `Promise.all` 后 `refreshAll()` 重渲染。

### 5.3 工资汇总与分摊（V3.6 替代原 genWageSheet）
- ~~`genWageSheet`（组级金额 → 成员分摊 → 写 wage）已删除~~。分摊改在「工资统计」页完成：`明细金额 = 子项数量 × 子项单价`（按 生产任务单 × 用料明细），`个人金额 = 工单组级金额 × 个人系数 ÷ 组内在职系数和`（`computePayStat`）。
- 汇总（结算页）只做**加总**，不再重算分摊：`wageSumRows()` 按 `工资月份 + 工号` 归并 paystat，得到 `计件金额 / 明细条数`（涉及工单仍实时计算，仅用于审核弹窗，列表不展示该列）。
- 工资单号 `WG{YYYYMM}-{工号}`（`wageNoOf`），已存在则复用，不重复生成。

### 5.4 财务审核（auditWage 批量 / doWageAudit 单条）
- 批量 `auditWage`：对当前筛选中 `审核状态≠已审核` 的**汇总行**先 `ensureWageRecord` 补齐 wage 记录，再统一置「已审核」+ 审核人 + 结算日期（本地墙钟 `nowStamp()`）。
- 单条：`openWageAuditSum(月份, 工号)` → `ensureWageRecord` → `openWageAuditOne(工资单号)` → `doWageAudit(no, true)`；驳回 → `审核状态=已驳回`。
- **V3.6 起审核不再回写 orders 的「结算状态」**（原按「所属小组」批量置已结算的逻辑已移除，避免误结与工单口径混淆）。

### 5.5 删除（delRecord）
- 二次确认弹窗 `confirmModal` → `db.deleteRecord({databaseId, recordId})` → `refreshAll()`。
- staff / groups / price 各自走对应 databaseId（事件委托分发）。

### 5.6 计件金额构成（renderWageChart）
- 入参 = 当前筛选后的 wage 行；按 `员工姓名` 聚合 `计件金额`；
- 输出：自适应网格卡片（姓名 + 金额 + 进度条 + 占构成百分比）。

## 7. 交互与事件机制

### 7.1 页面级事件（`bindEvents`）
- 导航、汉堡菜单、筛选 `change/input`、新增按钮、弹窗确定/取消、Esc 关闭。
- 弹窗「确定」(`modalOk`)：保存前 `attachDb()`，若 `db` 为空提示「数据库未连接」并阻断，避免静默失败。

### 7.2 表格按钮事件委托（document 级 click）
动态生成的按钮通过 `data-*` 属性标识，统一在 `document` 监听器分发：

| 属性 | 触发 | 处理 |
|---|---|---|
| `data-staff` / `data-group` / `data-price` | 编辑 | 打开对应表单 |
| `data-del-staff` / `data-del-group` / `data-del-price` | 删除 | `delRecord(对应dbId, id, label)` |
| `data-start-submit="单号\|子物料"` | 开工提交 | `openStartSubmit` |
| `data-audit-wage="工资单号"` | 工资审核 | `openWageAuditOne` |
| `data-audit-reject="工资单号"` | 驳回 | `doWageAudit(no, false)` |
| `data-oconfirm="单号\|子物料"` | 跳转确认页并预勾 | 切到 confirm 并勾选 |
| `data-sel-task="生产任务单号"` | 选中/取消选中该行 | 在 `#ordersBody` 上**直接绑定**（非 document 委托），联动 `renderOrders`+`renderMaterial`；行内按钮不触发 |

> ⚠️ 新增任何表格内按钮都必须在此委托中补分支，否则点击无反应。
> ⚠️ `data-sel-task` 是**行级**选择器而非按钮，故不走 document 委托（在 `#ordersBody` 上单独绑定），并需 `e.target.closest("button,input,a,label")` 排除行内操作。

### 7.3 选项来源
- `OPT_STATIC`：内置全量选项副本（防 schema 拉取失败导致下拉空白）。
- `OPT`：运行期 `shapeSchema` 覆盖后的实际选项。
- `optId(key, field, text)`：文本 → option id 反查（已是 id 则原样回传）。
- `groupNameOptions()`：小组名取自 groups 表实际记录 + staff 表出现过的组（该字段为文本候选，不依赖 schema）。
- `processNameOptions()`：工序名取自 price 字典 + 工单实际值 + 内置。

## 8. 数据同步与生命周期

- **加载**：`boot()` → `attachDb()` → `refreshAll()`（翻页 `query`，`pageSize:200`，游标续拉至空）→ `renderAll()`。
- **实时刷新**：`subscribeUpdates()` 注册 `db.onUpdated`，任一订阅表变更后 300ms 去抖 `refreshAll()`。
- **SDK 晚注入**：`boot()` 若 `db` 为空先渲染空态并 `waitForDb()` 轮询（约 10s），就绪后自动接管。
- **绑定标记**：渲染容器带 `data-sp-bindable="database"` + `data-sp-database-id`，JS 渲染后置 `markBound(root, dbId)` 通知资料库编辑器该区为数据库绑定。
- **草稿**：表单输入 `scheduleDraftSave` / `readDraft` / `writeDraft` / `clearDraft` 本地暂存，防止误关丢失。

## 9. 上传 / 静态校验规范（必须遵守）

1. **`--databases` 必带全 11 表**（见 §2.2），否则页面关联不到数据表，写操作被拒且静默。
2. **`--node-block-id M0TIXtwP3MogyZsqUVYiVm`** 原位更新，链接不变。
3. **`databaseId` 必须字符串字面量**：静态 lint 要求每处 SDK 调用的 `databaseId` 是字面量，故不抽取「带参通用查询」，而是每张表各自一份 `load_xxx` 翻页实现（§6 上方注释）。
4. **lint 排除 `.delete()`**：资料库 SDK 删除用 `deleteRecord`，不要写 `.delete()`，否则静态校验不通过。
5. **新增 select 写入**：必须用 `optId()` 取得 option id，传 `{ select: id }` 结构（不要直接传文本）。
6. **本地改动后**：语法校验（如 `node --check` 或 jsdom 模拟）通过后再 `import_html.py` 上传。

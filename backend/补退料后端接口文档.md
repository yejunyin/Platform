# 补退料（生产补料/生产退料）后端接口开发文档

**版本**: v1.0
**日期**: 2026-09-08
**关联需求**: 《按灯呼叫》小程序生产管理模块——快速领退料系统开发设计文档（08-按灯呼叫(生产补料和生产退料）.docx）
**前端状态**: 小程序端页面已开发完成（M1/M2/M4/M5 及记录查询、异常重试入口），**所有补退料数据均直接调用本后端服务**，无模拟数据；接口地址配置于 `utils/api-config.js` 的 `MATERIAL.BASE_URL`。

---

## 一、概述

### 1.1 业务背景

生产车间在制造过程中频繁发生补料与退料需求，传统纸质单据流转存在效率低、批次追溯难、多系统数据不同步等问题。本系统通过扫码驱动、移动端审批、FIFO自动匹配及 ERP/WMS 双系统联动，实现领退料业务的数字化闭环管理。

### 1.2 前后端分工

| 模块 | 归属 | 说明 |
| --- | --- | --- |
| M1 生产订单扫描 | 前端(已开发) + 后端校验 | 扫码/输入、防重复由前端保证；订单状态校验与数据由后端（金蝶生产订单）提供 |
| M2 物料清单展示 | 前端(已开发) + 后端查询 | 应发/已领/差异由后端调金蝶用料清单计算后返回 |
| M3 库存查询与批次匹配 | **后端开发** | FIFO 匹配、自动拆批、库存预占、部分匹配兜底 |
| M4 退料清单管理 | 前端(已开发) + 后端提交接口 | 数量上下限由前端限制并需后端二次校验 |
| M5 质检审核 | 前端(已开发) + 后端接口 | 通过(必选退料类型)/驳回(必填原因) |
| M6 ERP退料单+补料单生成 | **后端开发** | 调用金蝶 K3Cloud 标准 WebAPI 生成退料单并自动审核，同时生成补料单并审核 |
| M7 WMS出库申请 | **后端开发** | 目标仓库启用WMS时自动追加，失败独立标记 |
| M8 消息推送 | **后端开发** | 钉钉工作通知 + 超时升级(2h/4h) |

### 1.3 地址统一配置说明

小程序侧仅维护其直接调用的服务地址，收纳于 `utils/api-config.js`：

| 配置节 | 用途 | 使用方 |
| --- | --- | --- |
| `ANDON` | 安灯后端(iMark)基础地址、Basic认证（安灯其他业务用） | 小程序 |
| `MATERIAL` | 补退料**独立后端服务**地址(`http://localhost:8081`)、接口路径、BASIC_AUTH认证 | 小程序 |

> 1. 补退料所有接口走**独立后端服务** `http://localhost:8081`（路径前缀 `/DBMaterialCall`），不走安灯 iMark 网关；如该服务启用账号密码认证，将 `'Basic ' + Base64(用户名:密码)` 配置到 `MATERIAL.BASIC_AUTH`，小程序请求时自动携带 `Authorization` 请求头。
> 2. 金蝶K3Cloud 与 WMS 的地址由**本后端服务自行配置维护**，小程序不持有；金蝶**直接走标准的 K3Cloud WebAPI**（`*.common.kdsvc`），标准接口地址清单见本文档第五章。

## 二、通用约定

- **BaseURL**: `http://localhost:8081`（补退料**独立后端服务**，即 `MATERIAL.BASE_URL`，接口路径前缀 `/DBMaterialCall`）
- **请求头**: `Content-Type: application/json`；`token`: 登录接口返回的令牌（与现有安灯系统一致）；如启用账号密码认证另携带 `Authorization`（配置于 `MATERIAL.BASIC_AUTH`）
- **操作人标识**: 各接口统一带 `username` 查询参数（员工工号 staffCode），用于操作留痕
- **统一响应格式**:

```json
{ "status": 0, "msg": "success", "data": {} }
```

| status | 含义 |
| --- | --- |
| 0 | 成功 |
| 2 | 库存不足部分匹配（仅质检审核接口专用，见接口9） |
| 其他非0 | 失败，msg 为错误描述 |

- **数量**: 统一保留 2 位小数；**时间**: `yyyy-MM-dd HH:mm:ss`
- **前端封装位置**: `utils/material-api.js`

## 三、状态机设计

### 3.1 状态码定义

| 状态码 | 名称 | 说明 |
| --- | --- | --- |
| 0 | 草稿 | 预留 |
| 10 | 待质检审核 | 申请提交后初始状态 |
| 11 | 已驳回 | 质检驳回（附驳回原因） |
| 20 | 批次匹配中 | 质检通过后 FIFO 匹配库存 |
| 30 | 退料单生成中 | 调金蝶生成退料单(自动审核)及补料单(审核) |
| 31 | 退料单生成异常 | 金蝶接口重试3次均失败，需人工重试 |
| 40 | 退料单已生成 | 金蝶退料单号及补料单号已回写 |
| 41 | WMS申请异常 | WMS接口失败（不阻塞ERP侧流程） |
| 50 | WMS申请已生成 | WMS出库申请单号已回写 |
| 99 | 已完成 | 全流程闭环 |

### 3.2 状态流转

```
[10 待质检审核] --驳回--> [11 已驳回](终态)
      |
    通过(选定退料类型)
      ↓
[20 批次匹配中] → [30 退料单生成中] → [40 退料单已生成] → (仓库启用WMS? 是: [50 WMS申请已生成] / 否: 直接收尾) → [99 已完成]
                        |
                        ↓(失败)
                  [31 退料单生成异常] --人工重试-->
                        ↓(WMS调用失败, 仅启用WMS仓库)
                  [41 WMS申请异常] --人工重试--> [50]
```

> M6 阶段（30→40）：调金蝶**生成退料单并自动审核**，**同时生成补料单并审核**；退料单号回写 `erpOrderNo`，补料单号回写 `erpReplenishOrderNo`（申请记录详情中在ERP退料单号下方展示，便于用户在金蝶查找两张单据）。

## 四、接口明细（小程序 ⇄ 安灯后端）

### 接口1：获取生产订单信息

- **封装函数**: `material-api.js - getOrderInfo(orderCode)`
- **地址**: `GET /DBMaterialCall/getOrder?orderCode={orderCode}&username={staffCode}`
- **后端处理**: 调金蝶 `PRD_MO` 查询订单；**仅"已下达(1)"和"生产中(2)"状态的订单允许补料**，其他状态或不存在时返回失败（status≠0，msg 说明原因，如"订单状态为[已完工]，仅已下达/生产中状态订单允许补料"）
- **返回数据**:

```json
{
  "status": 0, "msg": "success",
  "data": {
    "orderCode": "MO20260907001",
    "erpOrderCode": "PP2026090701",
    "productCode": "CP0001",
    "productName": "精密减速齿轮箱GX-200",
    "planQty": 500,
    "producedQty": 320,
    "orderStatus": 2,
    "orderStatusText": "生产中",
    "planEndTime": "2026-09-10"
  }
}
```

> `orderStatus`: 1已下达 2生产中 3已完工（其他值前端一律拦截）

### 接口2：获取订单用料清单

- **封装函数**: `material-api.js - getOrderMaterials(orderCodes[])`
- **地址**: `GET /DBMaterialCall/getOrderMaterials?orderCodes={code1,code2}&username={staffCode}`（逗号分隔，支持多订单）
- **后端处理**: 调金蝶 `PRD_PPBOM` 用料清单 + 已领料数据，计算差异数量 `diffQty = shouldQty - issuedQty`（应发-已领，可为0）
- **返回数据**（按订单分组）:

```json
{
  "status": 0, "msg": "success",
  "data": [
    {
      "orderCode": "MO20260907001",
      "productName": "精密减速齿轮箱GX-200",
      "materials": [
        {
          "materialCode": "WL0002",
          "materialName": "铝合金外壳",
          "spec": "A6061-T6",
          "unit": "件",
          "shouldQty": 500,
          "issuedQty": 420,
          "diffQty": 80,
          "stockQty": 260
        }
      ]
    }
  ]
}
```

> `stockQty` 为当前可用库存（即时库存，供参考展示）；`diffQty <= 0` 的物料前端自动禁用"加入补料"。

### 接口3：获取补料原因字典

- **封装函数**: `material-api.js - getReasonList()`
- **地址**: `GET /DBMaterialCall/getReasons?reasonType=1`（reasonType=1 补料原因，预留扩展）
- **返回数据**:

```json
{ "status": 0, "msg": "success", "data": [{ "id": 1, "name": "生产超损耗" }] }
```

### 接口4：获取质检员列表

- **封装函数**: `material-api.js - getQcStaffList()`
- **地址**: `GET /DBMaterialCall/getQcStaffList?username={staffCode}`
- **后端处理**: 从员工表筛选质检岗位人员（可按角色/部门过滤）
- **返回数据**:

```json
{
  "status": 0, "msg": "success",
  "data": [{ "staffInfoDBId": "QC1001", "staffCode": "HL202301001", "staffName": "王建国" }]
}
```

### 接口5：提交补退料申请（M4 → M5入口）

- **封装函数**: `material-api.js - submitMaterialCall(payload)`
- **地址**: `POST /DBMaterialCall/submit?username={staffCode}`
- **请求体**:

```json
{
  "applicantStaffId": "员工数据库ID",
  "applicantName": "申请人姓名",
  "reasonId": 1,
  "reasonText": "生产超损耗",
  "qcStaffId": "QC1001",
  "qcStaffName": "王建国",
  "orderList": [
    {
      "orderCode": "MO20260907001",
      "materials": [
        { "materialCode": "WL0002", "materialName": "铝合金外壳", "spec": "A6061-T6", "unit": "件", "qty": 80 }
      ]
    }
  ]
}
```

- **后端处理**:
  1. 服务端二次校验：数量 0 < qty ≤ 可补数量(diffQty)；补料原因、质检员必填
  2. 生成申请单（单号规则建议 `TL + yyyyMMddHHmmss`），状态置 **10 待质检审核**
  3. 推送钉钉工作通知至质检员（M8）
- **返回数据**:

```json
{ "status": 0, "msg": "success", "data": { "id": "10001", "callNo": "TL20260908090101", "status": 10 } }
```

  "data": [

      "id": "10001",
      "callNo": "TL20260908090101",
      "status": 10,

      "qcStaffName": "王建国",
      "reasonText": "生产超损耗",
      "orderCodes": "MO20260907001,MO20260907002",

      "erpReplenishOrderNo": "",
      "wmsOrderNo": "",

> `erpOrderNo` 为金蝶退料单号，`erpReplenishOrderNo` 为金蝶补料单号（审核通过后回写，前端在申请记录ERP退料单号下方展示，便于用户在金蝶查找记录）。

### 接口9：质检审核（M5 → 触发 M3/M6/M7 流水线）

- **封装函数**: `material-api.js - auditMaterialCall(params)`（**返回原始响应，前端需识别 status=2 部分匹配**）
- **地址**: `POST /DBMaterialCall/audit?username={staffCode}`
- **请求体**:

```json
{
  "id": "10001",
  "auditStaffId": "HL202301001",
  "auditStaffName": "王建国",
  "auditResult": 1,
  "returnTypeId": 1,
  "rejectReason": "",
  "forceFlag": 0
}
```

| 字段 | 说明 |
| --- | --- |
| auditResult | 1通过 / 2驳回 |
| returnTypeId | **通过时必填**: 1良品退料 2不良品退料 3报废退料 |
| rejectReason | **驳回时必填**，随消息推送给申请人 |
| forceFlag | 0默认；库存不足部分匹配时，前端经用户确认后以 forceFlag=1 重发（按最大可用量继续） |

- **后端处理（通过时同步/异步执行流水线）**:
  1. 状态 10 → 20 批次匹配中：按 M3 规则 FIFO 匹配（见第七章）
  2. **若总可用库存不足且 forceFlag=0**：返回 `status=2`，data 携带 `{ "requestQty": 1200, "matchQty": 800 }`，申请单保持待处理状态
  3. 匹配成功 → 30 退料单生成中：调金蝶生成退料单并自动审核，同时生成补料单并审核（M6，见第五章）→ 40
  4. 若批次/仓库 wmsFlag=true → 调 WMS 生成出库申请（M7）→ 50 → 99；WMS失败单独置 41，不阻塞 ERP 侧
  5. 推送消息：通过→申请人+仓管员；驳回→申请人（附原因）
- **返回数据**:

```json
// 成功
{ "status": 0, "msg": "success", "data": { "id": "10001", "status": 99, "erpOrderNo": "TLGD...", "erpReplenishOrderNo": "BLGD...", "wmsOrderNo": "WMS..." } }

// 库存不足部分匹配（forceFlag=0时）
{ "status": 2, "msg": "库存不足", "data": { "requestQty": 1200, "matchQty": 800 } }
```

### 接口10：重试生成ERP退料单/补料单（M6异常兜底）

- **封装函数**: `material-api.js - retryErpOrder(id)`
- **地址**: `POST /DBMaterialCall/retryErpOrder?id={id}&username={staffCode}`
- **后端处理**: 仅状态=31 时允许；重新调金蝶生成退料单及补料单（已成功生成的单据不重复生成，仅补生成缺失单据），成功后置 40（若需WMS则继续 50→99），失败保持 31 并更新 errorMsg
- **返回数据**: `{ "status": 0, "msg": "success", "data": { "id": "10001", "status": 40, "erpOrderNo": "TLGD...", "erpReplenishOrderNo": "BLGD..." } }`

### 接口11：重试生成WMS出库申请（M7独立重试）

- **封装函数**: `material-api.js - retryWmsOrder(id)`
- **地址**: `POST /DBMaterialCall/retryWmsOrder?id={id}&username={staffCode}`
- **后端处理**: 仅状态=41 时允许；**无需重新生成ERP退料单**，仅重发WMS申请，成功后置 50 → 99，失败保持 41 并更新 errorMsg
- **返回数据**: `{ "status": 0, "msg": "success", "data": { "id": "10001", "status": 50, "wmsOrderNo": "WMS..." } }`

## 五、金蝶 K3Cloud 标准接口对接（后端，M2/M3/M6）

> 所有金蝶调用**直接走金蝶标准 WebAPI**，服务器地址、账套ID、登录账号密码由**本后端服务自行配置维护**（小程序侧不持有金蝶配置）。

### 5.1 标准接口地址清单

| 用途 | 地址（相对 `KINGDEE.BASE_URL`） |
| --- | --- |
| 登录验证 | `/Kingdee.BOS.WebApi.ServicesStub.AuthService.ValidateUser.common.kdsvc` |
| 单据列表查询 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.ExecuteBillQuery.common.kdsvc` |
| 表单数据加载 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.Load.common.kdsvc` |
| 单据保存 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.Save.common.kdsvc` |
| 单据提交 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.Submit.common.kdsvc` |
| 单据审核 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.Audit.common.kdsvc` |
| 单据反审核 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.UnAudit.common.kdsvc` |
| 单据下推 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.Push.common.kdsvc` |
| 批量保存 | `/Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.BatchSave.common.kdsvc` |

涉及业务对象（FormId）：

| FormId | 业务对象 | 用途 |
| --- | --- | --- |
| `PRD_MO` | 生产订单 | 接口1订单校验（状态：已下达/生产中） |

| `STK_Inventory` | 即时库存 | M3 FIFO 批次/库位匹配 |

| `PRD_FeedMtrl` | 生产补料单 | M6 补料单生成（生成后审核） |

### 5.4 生产退料单/补料单生成（M6）

## 六、WMS 出库申请对接（后端，M7）

> WMS 服务地址由**本后端服务自行配置维护**（小程序侧不持有WMS配置）。

- **触发条件**：仅当批次匹配结果中目标仓库 `wmsFlag=true`（启用WMS管理）时触发，非WMS仓库跳过并直接通知仓管员入库
- **请求示例**:

```json
POST {WMS.BASE_URL}/outbound/apply
{
  "sourceOrderNo": "TL20260908090101",
  "erpOrderNo": "TLGD20260908100001",
  "warehouse": "原材料仓",
  "items": [
    { "materialCode": "WL0003", "batchNo": "PC20260715-02", "locationCode": "B-03-01-1", "qty": 800 }
  ]
}
```

- **响应约定**: `{ "code": 0, "data": { "wmsOrderNo": "WMS20260904005" } }`
- **规则**：
  - WMS申请单与ERP退料单强关联，任一单据异常不影响另一单据正常流转
  - WMS接口失败**单独标记状态 41**，不阻塞ERP侧流程，但触发专项告警
  - 支持独立重试（接口11），无需重新生成ERP退料单

## 七、FIFO 库存匹配规则（M3）

1. **FIFO强制执行**：严格按批次入库时间升序分配，最早入库批次优先消耗，不允许跳跃式选择
2. **自动拆批**：单一批次库存不足时自动拆分至下一批次，直至满足退料总量
3. **库存预占**：匹配成功后对相关批次进行逻辑预占（预占表/预占字段），防止并发操作导致超发
4. **异常兜底**：总可用库存不足时，返回最大可用量并标记"部分匹配"（status=2），由操作员决定是否继续（forceFlag=1 按最大可用量继续）
5. **WMS标识透传**：匹配结果携带目标仓库是否启用WMS标识（wmsFlag），作为M7流程分支判断依据

## 八、消息推送（M8，后端）

- **渠道**：钉钉工作通知（卡片消息，含摘要/操作按钮/H5跳转链接，一键进入对应功能页面）
- **场景模板**（独立配置，支持扩展）：

| 场景 | 接收人 | 内容要点 |
| --- | --- | --- |
| 申请提交 | 质检员 | 单号、申请人、订单、物料数、跳转审核页 |
| 审核驳回 | 申请人 | 单号 + 驳回原因 |
| 审核通过/退料单生成 | 申请人 + 仓管员 | 退料单号、批次库位 |
| ERP生成异常(31) | 管理员 | 申请单号 + 错误信息 |
| WMS生成异常(41) | 管理员 | 申请单号 + 错误信息 |
| 超时2h | 质检员 | 待审核提醒 |
| 超时4h | 质检员直属主管 | 升级通知 |

- **降级策略**：推送失败自动降级为站内消息+邮件双重通知，确保消息不丢失
- **持久化**：所有推送记录落库，支持按时间、对象、状态多维度查询与重推
